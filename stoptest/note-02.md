# Targeting Rules and User Segmentation

Targeting rules are the mechanism that transforms a feature flag from a simple on-off switch into a precision instrument for controlled delivery. At its core, targeting evaluates attributes of a context—typically a user, but increasingly a device, organization, or service—against a set of rules to determine which variation of a flag that context receives. Simple rules might match on a single attribute, such as email domain or country, while sophisticated rules combine multiple clauses with operators like contains, matches, greater-than, or semantic version comparisons. Segments elevate this further by letting teams define reusable audiences, such as beta testers, enterprise customers, or internal employees, that can be referenced across many flags simultaneously. When a segment definition changes, every flag targeting that segment updates instantly, which centralizes audience management and reduces configuration drift. Rule ordering matters enormously: evaluation typically proceeds top-down, with the first matching rule winning, so teams must think carefully about precedence when stacking individual targets, segment rules, and percentage rollouts. Well-designed targeting also demands consistent context attributes across services, because a rule matching on plan-type fails silently if one service sends planType instead. Disciplined attribute schemas and documented rule conventions keep targeting predictable and debuggable at scale.
